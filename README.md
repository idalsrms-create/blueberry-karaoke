# 블루베리 노래방

**서울말 억양을 노래방처럼 익히는 웹앱.**

> **서울 기준 표준어를, 다른 지역 사람이 배우려고 쓰는 앱이다.**
> 설계가 흔들릴 때마다 이 문장으로 돌아온다.

지방 사람이 서울말을 익힐 때 가장 어려운 게 억양이다. 글로는 배울 수가 없다.
그래서 **음의 높낮이를 눈에 보이게** 그려 주고, 들려주고, 마이크로 **서울말과 어디가 다른지** 짚어 준다.

```
문장을 적는다  →  들어 본다  →  억양 막대를 따라 읽는다  →  서울말과 어디가 달랐는지 본다
```

**사투리는 틀린 말이 아니다.** 이 앱은 고치는 도구가 아니라 **하나를 더 익히는** 도구다.
그래서 화면에서 "틀렸다"고 말하지 않는다 — **"서울에서는 이렇게 읽어요"** 라고 쓴다.

> 📄 **왜 그렇게 정했는지는 [DESIGN.md](DESIGN.md) 에 다 적어 뒀다.**
> 기술 선택, 억양 기준을 어디서 가져올지, 채점 방법, 화면 구상, 모르는 것까지.

---

## 지금 상태: **기초** (바닥 깔기)

완성품이 아니다. 하지만 **네 단계 흐름이 끝까지 한 번 돈다.**

```
문장 입력  →  듣기  →  [시작]  →  마이크로 읽기  →  서울말과 어디가 다른지 표시
```

- ✅ **먼저 들어 보기** — 문장을 소리 내어 읽어 준다. 들은 **박자에 막대 길이가 맞춰진다**
- ✅ 노래방 화면 — **음표 막대 · 지나가는 커서 · PERFECT 판정 · 아래 큰 문장**
- ✅ 내 목소리 곡선이 기준 막대 위에 **실시간으로 겹쳐** 그려짐
- ✅ 채점 — 모양 / 폭 / 겹친 비율 + **음절별로 몇 반음 어긋났는지**
- ⚠️ **막대의 출처가 아직 "규칙"이다 — 정답이 아니다.**
  진짜 기준은 진행자가 직접 읽은 녹음이다(DESIGN.md 3장). 그래서 화면에 경고를 띄워 뒀다.
- ❌ 진행자 녹음 저장·들려주기 — 다음 할 일

### 확인된 숫자 (실제로 브라우저에서 측정)

| | |
|---|---|
| 정확도 (90~400Hz) | 오차 **±0.3센트 이내** (반음의 1/300) |
| 속도 | **0.208 ms / 프레임** — 60fps로 돌려도 CPU 1.2% |
| 옥타브 오류 함정 시험 | 통과 (기본음이 깎인 소리도 정확) |
| 외부 라이브러리 | **없음** (McLeod Pitch Method 직접 구현, 약 120줄) |

## 실행 방법

터미널(PowerShell)에서 이 폴더로 간 다음:

```bash
node serve.mjs
```

그리고 **크롬이나 엣지**에서 열기:

```
http://localhost:5173
```

### 🔊 듣기 — 이 컴퓨터엔 **여성 음성 하나뿐**입니다

Windows에 설치된 한국어 음성이 `Microsoft Heami(여성)` 하나라서,
**남성 음성 버튼은 띄우지 않았습니다**(없는 걸 있는 척하지 않으려고).
대신 같은 음성을 낮춘 `🔉 낮은 목소리` 버튼을 뒀고, 화면에도 그게 남성 음성이 아니라고 써 뒀습니다.

진짜 남성 음성이 필요하면 셋 중 하나입니다 (자세히는 [DESIGN.md 3.6장](DESIGN.md)):
1. Windows에 한국어 남성 음성 추가 설치 → **버튼이 저절로 늘어납니다**
2. 크롬에 네트워크 음성이 더 있을 수 있음 → **크롬에서 열어 보면 바로 확인됩니다**
3. 서버 TTS(Azure·Google) → 남녀 여러 음성 + 기준 곡선까지 해결

### ⚠️ 두 가지 주의

1. **`index.html` 을 더블클릭해서 열면 마이크가 안 된다.**
   브라우저는 `file://` 로 연 페이지에 마이크를 안 준다. 반드시 위처럼 `localhost` 로 띄워야 한다.
   `serve.mjs` 가 있는 이유가 그것뿐이다. (Node 내장 기능만 쓰므로 `npm install` 필요 없음)

2. **마이크 권한을 물어보면 "허용"을 눌러야 한다.**
   거부하면 페이지 아래 로그에 빨간 글씨로 이유가 뜬다.

### 마이크 없이도 확인할 수 있다

입력을 **"🧪 시험용 소리(마이크 없이)"** 로 바꾸고 시작하면,
브라우저가 **기준 막대를 일부러 조금 틀리게 따라가는 소리**를 만들어 넣는다.
마이크 권한과 무관하게 화면과 채점이 어떻게 도는지 눈으로 볼 수 있다.
(연습이 아니라 **확인용**이다)

> 참고: Claude가 쓰는 앱 내장 브라우저 패널에서는 **마이크가 정책상 완전히 차단**돼 있어
> (`NotAllowedError`, 권한 창조차 안 뜸) 마이크 경로만은 사람이 직접 확인해야 한다.
> 나머지는 전부 검증했다. 자세한 내용은 DESIGN.md 7장.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | **연습 화면.** 문장 입력 → 막대 → 읽기 → 채점 |
| `pitch.js` | 소리에서 음 높낮이(F0) 뽑기. 두 페이지가 같이 쓴다 |
| `intonation.js` | 문장 → **임시** 기준 막대 (K-ToBI 규칙). ⚠️ 정답 아님 |
| `tts.js` | 읽어 주기 + 어절 박자 받아오기 |
| `pitch-demo.html` | 피치 추출만 떼어 본 시연·검증용 페이지 |
| `serve.mjs` | 로컬 서버. 마이크를 쓰려면 `localhost` 가 필요해서 있다 |
| `DESIGN.md` | **설계 결정과 근거.** 이 프로젝트의 본체에 가깝다 |
| `참고-노래방-음정막대.jpg` | 목표 화면 참고 사진 (실제 노래방 기계) |
| `.claude/launch.json` | 개발 도구에서 서버를 띄우는 설정 |
